# Sentry — What We’re Building

**One page for partners & collaborators** · September 2026

---

### The problem
Company knowledge lives in people’s heads, Slack threads, and old chats.  
Every new project restarts the same explanations. Every new hire relearns “how we do things here.”  
Generic AI invents answers. Spreadsheets and wikis don’t keep up with the work.

### The promise
**Sentry is the company watcher** — private institutional memory your team can ask.

- Answers from *your* policies, SOPs, and exports — **cite or refuse**, never invent.
- Named **agents** propose domain work (billing, shipping, IT, books, standards); **humans approve**.
- A **desktop home** for the day: chats, meetings, library updates — what needs you next.
- **Asks** for collaborative work: shared ownership, not another lost task list.

### What’s different: Knowledge Pills
When two projects share a lot and differ a little, you shouldn’t re-brief the model from scratch.

| | |
|---|---|
| **Make a pill** | Distill an existing chat into a compact capsule: goals, stack, decisions, constraints. |
| **Attach it** | Drop that pill into a new chat (or related project thread). |
| **Ask only the delta** | Shared context = **N**. What’s new = **K**. The model already has N — you only teach K. |

**Example:** Project A and Project B share onboarding flow, stack, and compliance rules (N).  
B only changes pricing and region (K). Attach A’s pill → start from K, not from zero.

That’s how Sentry turns past work into reusable prior — without dumping whole transcripts into every new conversation.

### Trust rules (non-negotiable)
1. **Cite or refuse** company facts — no hallucinated policies or numbers.  
2. **Chat = shared · Sidekick = personal** — walls stay clear.  
3. **Agents propose; people approve** — no silent write-backs.  
4. **Hard workspace isolation** on every query.

### Who it’s for
5–50 person teams (agencies, professional services, light ops) where “how we work” still lives in a few people’s heads — and every similar project burns the same ramp-up time.

### Success we care about
- Time-to-useful answer for someone new to a topic or project  
- Reuse of pills across related work (less re-briefing)  
- Answers operators can act on — with sources when it matters  

---

**Bottom line:** Sentry makes the company knowable — and makes the next project inherit the last one, so teams only solve what’s actually new.
